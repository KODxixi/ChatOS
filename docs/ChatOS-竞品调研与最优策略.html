ChatOS 的最优策略：
做微信记忆的本地外挂

ChatOS 是本地 AI 助手（Claude Code、OpenClaw 等）的「微信记忆层」——记住你和谁聊过什么、聊了什么，让 AI 随时能查。本次调研 13 个同类产品，全部事实经独立核查后，给出可直接执行的最优路线。

对标 2 个：Cognee · basic-memory 借鉴 4 点：事实演化 · 混合检索 · 文件即真相 · 记忆抽取 避开 5 个坑：云阉割 · 绑框架 · 图数据库 · 逆向解密 · 录一切
01
最优策略 · 结论先行
一句话 + 三个抓手 + 下一步动作，按优先级排序
核心判断

ChatOS 不需要重造轮子，也不需要追赶大厂。
它应该成为「微信记忆」这个细分赛道的唯一选手：只读、全本地、开放给所有 AI。

调研结论：没有第二个产品同时满足「读微信聊天记录 + 全本地模型 + 给外部 agent 当记忆 API」。Mem0/Letta/SuperMemory 想赚云的钱，Khoj/basic-memory 不碰微信数据，OpenClaw 的记忆只记「AI 自己聊过什么」，不记「你微信聊过什么」。这个空位就是 ChatOS 的。策略 = 对标两个被验证的本地产品补齐工程短板，避开五个已经被市场证明的坑，然后专注做好「微信」这一个数据源的体验。

◆ 对标谁
  • Cognee：技术栈几乎一模一样（Python + SQLite + LanceDB），还自带 Claude Code / OpenClaw 的现成接入——照着它的架构抄作业，成本最低。
  • basic-memory：证明「一行配置接入 Claude」能做到什么程度；它的混合检索 + 本地重排管道可以直接借鉴。
◆ 借鉴什么
  • 「事实会变」（Graphiti）：他说过喜欢 A、后来改主意了——旧记忆不删除，标记「已被取代」。聊天记录里这种事天天发生。
  • 混合检索 + 本地重排（Khoj / basic-memory）：关键词 + 语义双通道，再本地重排，又准又稳。
  • 文件即真相（OpenClaw）：记忆保存成能看懂、能手改的文件，人和 AI 都能校对。
  • 从对话抽结构化记忆（LangMem）：把「偏好 / 关系 / 项目」抽成卡片，而不是只存原文。
◆ 避开什么
  • 云优先的阉割（Mem0）：好功能搬去云端，开源版缺斤少两——ChatOS 的核心价值是「数据不出本机」，绝不能走这条路。
  • 绑架你的 AI（Letta）：要求把 agent 搬进它家跑——ChatOS 是外挂，不是家。
  • 图数据库（Graphiti 的实现）：时序思路值得学，但为它上 Neo4j 太重。
  • 逆向解密（WeChatMsg 前车之鉴）：原版已被腾讯 DMCA 下架——只读现有数据库，绝不碰解密，这是生死线。
  • 「录一切」路线（Rewind）：已被市场证伪（2025 年底关停）；ChatOS 的轻量投影路线更稳。
P0 · 立即做

① 接上 MCP —— 让 AI「一行配置」就能查微信记忆

这是当前行业标准接口：Claude Code、OpenClaw 等都原生支持。ChatOS 已有 HTTP API，缺的只是这层「插头」；对标 Cognee / basic-memory 的现成 MCP 接入方式。

为什么第一：不做这一步，AI 用不上 ChatOS，前面全是空谈。
P0 · 立即做

② 检索升级：关键词 + 语义 + 本地重排

BM25 全文检索 + 向量语义检索双通道合并，再加一个本地小模型做重排（llama-swap 就能跑）。对标 basic-memory / Khoj 已验证的管道，消费级电脑跑得动。

为什么第一：「记得住」和「找得准」是两个能力；目前只有向量，找聊天里的具体细节会不准。
P1 · 紧接着做

③ 轻量版「事实演化」：旧记忆标记「已被取代」

借鉴 Graphiti 的时序思路，但只用 SQLite / LanceDB 轻量实现：给每条记忆加状态字段，新事实进来旧事实自动标记 superseded，绝不物理删除。微信里「改主意、换说法」的场景天然需要它。

为什么第二：不删旧记忆，AI 才能理解「一个人是怎么变的」，这是记忆层区别于搜索库的本质。
P1 · 紧接着做

④ 结构化记忆卡片：偏好 / 关系 / 项目

从对话里抽取「他喜欢什么、讨厌什么、我们在做什么项目」，存成可读文件（借鉴 OpenClaw 的 MEMORY.md + LangMem 的抽取设计），人和 AI 都能看、能改。

为什么第二：原文检索是「找证据」，记忆卡片是「直接可用」，两者互补。
P2 · 有空再做

⑤ 合规自查 + 实时新消息通道

文档里写死边界：只读 SQLite、绝不逆向解密（WeChatMsg 被下架是前车之鉴）；新消息实时接收可参考 wechaty 思路，但微信侧合规风险高，务必谨慎、默认不做。

为什么靠后：合规是底线不是卖点；实时通道是锦上添花，检索做扎实之前不值得投入。

两条已证伪的路线（参考）

Rewind「录一切」：录屏 + OCR 记录你的一切操作——2025-12 被收购后 App 停用，产品实质终止；「录一切」太重（隐私 + 耗电），反衬 ChatOS「只读投影文字」更轻更稳。

Recall「系统记忆」：微软 Windows 自带屏幕快照回溯——系统级但完全封闭，不给第三方 AI 任何接口；ChatOS 的开放 HTTP API 反而是 AI 唯一能用的本地记忆通道。

一句话总结市场格局

通用记忆赛道已经拥挤，但「微信」这个数据源无人占领。Mem0 / Letta / SuperMemory 抢的是「云 + 通用」，basic-memory / Khoj 抢的是「本地 + 通用」，OpenClaw 记的是「AI 自己的事」，WeChatMsg 只管导出、wechaty 只管收发。

ChatOS 的护城河 = 微信 SQLite 只读投影 + 常驻检索 API + 全本地模型。三者同时满足的，目前没有第二家。
